# 아트록스 1280x1024 패치

아트록스 실행파일을 고쳐 1280x1024 해상도로 실행되게 한다. 해상도 모드 1 의 화면 크기를 800x600 에서 1280x1024 로 바꾸고, 800x600 기준으로 놓인 인터페이스 좌표를 넓어진 화면의 아래쪽 가운데로 옮긴다. 전체 화면판과 창모드판 두 가지가 있다.


## 대상

| 항목 | 값 |
|---|---|
| 게임 | 아트록스 v1.10 빌드 1 |
| 파일 | UPX 를 푼 `atrox.exe` (2,965,504바이트) |
| md5 | `b4c64c06c2afd830995ef497478718be` |

정품 `atrox.exe` (md5 `01d0c56a04f61ffa40d219eb0378154c`) 는 UPX 로 압축되어 있다. `upx -d` 로 푼 파일이 위 표의 파일이다.

이미지 베이스는 `0x400000` 이고 고친 곳은 전부 `.text` 섹션(가상 주소 `0x401000`, 파일 오프셋 `0x1000`) 안이다. 그래서 **파일 오프셋 = 가상 주소 - 0x400000** 이다.


## 조합

| 판 | 넣는 표 |
|---|---|
| 전체 화면 1280x1024 | 표 1, 표 2 (표 3 은 넣어도 되고 빼도 된다) |
| 창모드 1280x1024 | 표 1 과 [창모드 패치](https://github.com/wnsrn3436/re-atrox-window-mode/blob/main/docs/window-mode.ko.md)의 표 전체 |

표 2 는 창모드 패치의 일부와 같은 바이트다.

## 표 2. 해상도 모드 고정과 시작 위치

| 가상 주소 | 파일 오프셋 | 원래 바이트 | 바꾼 바이트 | 의미 |

| `0x004894EB` | `0x894EB` | `CC` 13개 | `B8 01 00 00 00 50 E8 E1 80 F7 FF EB 32` | 해상도 모드 1 을 넘긴다 |

## 표 3. 스크롤 우회 경로

| 가상 주소 | 파일 오프셋 | 원래 바이트 | 바꾼 바이트 | 의미 |
|---|---|---|---|---|
| `0x0042D477` | `0x2D477` | `56 E8 FD 9D FD FF` | `EB 3C 90 90 90 90` | 첫 스크롤 호출을 아래로 돌린다 |
| `0x0042D481` | `0x2D481` | `53` | `90` | `push ebx` 를 아래로 옮긴다 |
| `0x0042D484` | `0x2D484` | `E8 8B 4F FD FF` | `EB 3A 90 90 90` | 둘째 스크롤 호출을 아래로 돌린다 |
| `0x0042D4B5` | `0x2D4B5` | `90` 11개 | `90 90 90 56 E8 BC 9D FD FF EB BD` | 첫 호출 |
| `0x0042D4C0` | `0x2D4C0` | `CC` 16개 | `90 90 90 53 E8 4B 4F FD FF EB BE 90 90 90 90 90` | 둘째 호출 |

창모드 패치의 스크롤 우회 경로에서 `sar esi, 3` 과 `sar ebx, 3` 자리를 `90 90 90` 으로 비운 것이다. 호출을 옮겼다가 그대로 돌아오기만 하므로 원본과 똑같이 동작한다. 전체 화면판 실행파일에 들어 있던 바이트라 함께 적었다.


## 해상도 모드 1 을 1280x1024 로

`0x004DC840` 은 해상도 모드를 받아 화면 크기를 정하는 함수다. 원래 모드 0 은 640x480, 모드 1 은 800x600 이다. 표 2 로 모드를 늘 1 로 넘기게 하고, 표 1 의 앞 네 줄로 모드 1 의 값을 바꿨다.

```
004DC85A  E8 26 BD F2 FF        call 0x00408585      ; 전역 객체 0x00B1DE78 을 돌려준다
004DC85F  C7 40 20 00 05 00 00  mov  [eax+0x20], 1280 ; 너비 (원래 800)
004DC866  E8 1A BD F2 FF        call 0x00408585
004DC86B  C7 40 24 00 04 00 00  mov  [eax+0x24], 1024 ; 높이 (원래 600)
004DC872  8B 4E 74              mov  ecx, [esi+0x74]
004DC875  B8 00 05 00 00        mov  eax, 1280        ; 원래 800
004DC87A  2B C1                 sub  eax, ecx
004DC87C  B9 B0 03 00 00        mov  ecx, 944         ; 원래 480
004DC881  89 46 7C              mov  [esi+0x7C], eax
004DC884  8B 46 78              mov  eax, [esi+0x78]
004DC887  2B C8                 sub  ecx, eax
004DC889  89 8E 80 00 00 00     mov  [esi+0x80], ecx
```

`[esi+0x7C]` 와 `[esi+0x80]` 이 무엇의 범위인지, 그리고 480 에 대응하는 값이 왜 944 인지는 추가 확인 대상이다.


## 인터페이스 좌표 옮기기

아래쪽 인터페이스와 관련 요소의 위치는 800x600 화면에 맞춘 상수로 코드에 들어 있다. 모든 x 에 240, y 에 424 를 더했다. 240 은 (1280 - 800) / 2, 424 는 1024 - 600 이라, 800x600 크기의 인터페이스가 1280x1024 화면의 아래쪽 가운데에 붙는다.

```
0041D20D  83 EC 10              sub  esp, 0x10
0041D210  B9 55 03 00 00        mov  ecx, 853         ; 원래 429
0041D215  8B EC                 mov  ebp, esp
0041D217  BA 20 03 00 00        mov  edx, 800
0041D21C  BB C8 00 00 00        mov  ebx, 200
...
0041D268  C7 05 48 65 6A 00 31 03 00 00  mov [0x006A6548], 817   ; 원래 577
0041D272  C7 05 4C 65 6A 00 7D 03 00 00  mov [0x006A654C], 893   ; 원래 469
...
00423849  C7 05 68 BC 6A 00 F8 02 00 00  mov [0x006ABC68], 760   ; 원래 520
00423853  C7 05 6C BC 6A 00 B3 03 00 00  mov [0x006ABC6C], 947   ; 원래 523
```

`0x0041D119` 의 `mov eax, 1` 은 모드 1 쪽으로 갈라지는 `0x0041D20D` 블록에서 사각형의 x 로 쓰인다. 그래서 1 을 241 로 바꿨다.

`0x0041D9EC` 는 화면 크기의 절반을 구해 무언가를 화면 가운데에 놓는 자리다. 높이의 절반 대신 (높이 + 424) / 2 를 쓰도록 빈자리 `0x0041D95B` 로 돌렸다. 1024 를 넣으면 724 가 되고, 이는 아래로 424 만큼 내려 놓은 800x600 영역의 가운데(300 + 424)다.

```
; 원본
0041D9E7  E8 99 AB FE FF     call 0x00408585
0041D9EC  8B 40 24           mov  eax, [eax+0x24]  ; 높이
0041D9EF  99                 cdq
0041D9F0  2B C2              sub  eax, edx
0041D9F2  8B F0              mov  esi, eax
0041D9F4  D1 FE              sar  esi, 1            ; esi = 높이 / 2
0041D9F6  E8 8A AB FE FF     call 0x00408585

; 패치
0041D9EC  E9 6A FF FF FF     jmp  0x0041D95B
0041D95B  8B 40 24           mov  eax, [eax+0x24]
0041D95E  05 A8 01 00 00     add  eax, 424
0041D963  99                 cdq
0041D964  2B C2              sub  eax, edx
0041D966  8B F0              mov  esi, eax
0041D968  D1 FE              sar  esi, 1            ; esi = (높이 + 424) / 2
0041D96A  E9 87 00 00 00     jmp  0x0041D9F6
```

가운데에 놓이는 것이 무엇인지는 추가 확인 대상이다.


## 직접 패치하기

1. 정품 `atrox.exe` 를 `upx -d` 로 풀고 md5 가 `b4c64c06c2afd830995ef497478718be` 인지 확인한다.
2. 위 조합 표에서 고른 판의 표를 헥스 에디터로 적용한다. 파일 오프셋마다 원래 바이트가 맞는지 보고 바꾼 바이트로 덮어쓴다.
3. 전체 화면판에서 화면이 깨지면 `docs/Atrox 1280 x 1024.bat` 으로 실행한다. 윈도우 탐색기를 끄고 게임을 실행한 뒤, 아무 키나 누르면 탐색기를 다시 켠다. 배치 파일은 `C:\Program Files\Joymax\Atrox\Atrox 1280 x 1024.exe` 를 실행하므로, 고친 실행파일을 이 이름으로 두거나 배치 파일의 경로를 고친다.

```bat
@echo off
taskkill /f /im explorer.exe
"C:\Program Files\Joymax\Atrox\Atrox 1280 x 1024.exe"
echo 아무키나 누르면 다시 탐색기를 시작합니다.
pause >nul
start explorer.exe
```
